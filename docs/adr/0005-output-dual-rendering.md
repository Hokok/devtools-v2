# 输出区的两种渲染：文本是唯一真源，树只是视图

JSON 工具（格式化 / 提取 / 比对）的输出区提供两种**视图模式**：树视图（可折叠结构树）
与文本视图（CodeMirror 纯文本）。两者渲染的是**同一段输出字符串**；切换视图不产生、
不修改、不缓存任何新的"输出"。

## 理由

- 平台的共享产物出口——复制、发送到、另存为、通用文本操作、比对报告——全部以
  "输出是字符串"为契约（见 ADR-0004 的 Consequences）。树若成为第二种"输出"，
  这套出口就要逐个判断"当前是树还是文本"，不变量被打破。
- 树的所有交互都定义成**视图层导航**：逐节点复制是从输出文本里取切片、复制路径产出
  「定位路径」语法的字符串、点节点跳回文本视图是切换渲染方式。"树上做不了的"（文本
  操作、另存、发送）都留在头部工具栏，与视图无关。
- 超大 JSON（> 512KB 或 > 2 万节点）渲染 DOM 树的代价与 WebView 内存模型冲突
  （DESIGN.md §5 的空载/多 Tab 内存预算），故树视图有硬阈值，超阈回落文本并有就地提示。

## Consequences

- 头部工具栏动作（复制 / 发送到 / 文本操作 / 另存）**不随视图模式变化**，永远作用于
  输出文本；树视图只额外提供"逐节点复制"这类视图内动作。
- 树视图是**只读**的：不可编辑输出。要改输出回输入区改输入。
- 比对工具的树是**左右两棵独立树**，节点着色直接复用差异高亮的 range 与颜色语义；
  数组保持「数组整体标记」（整块标色，不逐元素对照），不引入左右合并树。
- 复制路径的语法 = CONTEXT.md 的「定位路径」（点路径 + `[n]`），与 JSON 提取的
  定位路径输入框同一方言，可互贴。
- 视图模式取值存工具配置（跟工具走、跨重启保留），不存会话历史。
- 树组件自研（复用 json-common/scan 的 span 与 cmTheme 语义色），不引入第三方
  JSON 树库——着色一致性、diff 标色与跳行都要与现有编辑器同源，外部库改造成本高于自研。
