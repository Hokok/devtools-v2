# 工具间传递只做单向发送，不做实时联动或管道

「发送到…」把一个工具的输出作为另一个工具新标签页的输入，是一次性的单向投递。平台**明确不做**：
标签页之间的实时联动（下游跟随上游输出变化）与可编排的管道（多工具串成数据流）。

## 理由

- 实时联动会引入标签页依赖图：上游变更 → 下游重算 → 需要环检测、失效传播、重算预算，与本项目
  "开 10 个 Tab 内存可控、切换零刷新"的简单模型直接冲突。
- 管道的价值可以用最原始的方式拿到——发送一次、在新标签页里继续编辑；把它做成常驻关系，
  反而让"每个标签页内容独立、会话即清"的语义变模糊。

## Consequences

- 传递只发生在"点击发送"那一刻；之后两个标签页彼此无关，可自由编辑与关闭。
- 未来若要做流水线，属于 ADR 级别的架构演进（需引入依赖图与失效传播），不能靠给现有动作加参数实现。
- 输出工具栏的共享动作（复制 / 发送 / 另存 / 文本操作）都以"当前输出字符串"为唯一输入，
  不持有对其他标签页的引用。
