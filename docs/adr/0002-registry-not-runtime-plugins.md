# 工具扩展采用构建期注册表 + 懒加载，明确不做运行时外部插件

新工具以"单体应用内的一个模块"形式接入：每个工具实现统一的 ToolDefinition 接口（元信息 + UI 组件 + 设置 schema），注册进中央 Registry，通过动态 import() 懒加载。这样加新工具 = 新增一个目录 + 一行注册，且类型安全、构建期可校验。**明确不做**运行时第三方插件加载（沙箱、权限、签名体系的安全成本远超 MVP 收益）——"插件"一词保留给未来可能的外部扩展机制，内置功能一律称"工具"。目录结构按 monorepo 边界预留，工具数量超过约 30 个或出现多人分工时再拆包。

## Consequences

- 第三方开发者无法为该应用编写工具；若未来需要，属于 ADR 级别的架构演进（需引入沙箱运行时）。
- 每个工具模块必须保持通过 `import()` 入口加载，禁止在 registry 元信息文件里直接 import 工具实现，否则懒加载失效。
