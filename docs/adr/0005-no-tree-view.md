# JSON 输出面板保持纯文本渲染（否决结构化树视图）

JSON 工具（格式化 / 提取 / 比对）的输出面板**不做** Apifox 式的可折叠结构树，
输出始终是 CodeMirror 纯文本渲染。做过一版树视图（默认树 + 文本可切）并实测后，
被验收否决，理由记录在此，防止将来重提。

## 理由（否决记录）

- **默认树打断主流程**：JSON 工具的价值链是「贴进去 → 看结果 → 复制走」，
  产出是文本本身。默认树把主体产物挡在了第二层交互之下，每次都得手动切回文本。
- **树的交互价值小**：靠 CodeMirror 已有的折叠槽、搜索高亮、语义着色，
  树能提供的"结构浏览"基本被覆盖；换来的却是第二套渲染面（ selections、
  diff 高亮、跳行、复制路径）都要与文本视图对账，复杂度不成比例。
- **观感天花板低**：自研树要追平 Apifox 那种做工，投入远大于收益；
  而"好看"这一诉求可以通过纯文本侧的语义配色升级满足。

## 后续

- 视觉诉求收敛到**编辑器语义色的可读性升级**（类型间拉开色相），见 `cmTheme.ts`。
- 若未来确有"按结构跳转"的诉求，优先考虑在文本侧增强（如 CodeMirror 折叠、
  大纲跳转插件），而不是第二套渲染面。
