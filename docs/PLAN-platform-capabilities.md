# 平台能力拓展计划（横切能力批次）

> 面向公开开发者、严守现有约束的一批**平台横切能力**：一次投入、所有工具受益，直击「复制粘贴来回倒腾」这一最大摩擦。
> 术语见 [CONTEXT.md](../CONTEXT.md)，决策见 [docs/adr/](./adr/)。

## 0. 前提与约束（已决策）

- **主轴**：平台横切能力（不是新增单工具，也不是纯壳层打磨）。
- **边界**：三条铁律不变（注册表只含元信息、`transform` 纯函数、设置 schema 化）；**不新增自定义 Rust 命令**；不解禁「会话不持久化」。
- **排序主准则**：摩擦减少量优先；tie-breaker 依次为通用性 > 成本 > 可见度。
- **持久化口径**：只有**应用偏好**（收藏、全局开关）落盘；**最近使用、会话历史、剪贴板历史**均为会话态，重启即清。

## 1. 能力清单与优先级

| 优先级 | 能力 | 一句话 | 消掉的摩擦 | 影响面 | 成本 |
|---|---|---|---|---|---|
| **P0** | 文件载入 / 拖拽导入 | 打开文件或把文件/文本拖进窗口，直接填进当前标签页输入区 | 找文件 → 复制 → 粘贴 | 全部工具 | M |
| **P0** | 工具间传递「发送到…」 | 输出区「发送到…」选目标工具，以当前输出作为新标签页输入 | 复制 → 切工具 → 粘贴 | 全部工具（异形工具各自定「产物」） | M |
| **P1** | 会话历史 | 每工具最近 ~20 条输入，可回填 / 删除 / pin | 手滑清空、想找回上次内容 | 全部工具 | S–M |
| **P1** | 应用内剪贴板历史 | 记录应用内复制过的文本，可再次复制或填回输入 | 丢粘贴板、反复复制 | 全部工具 | S–M |
| **P1** | 通用文本操作 | 输出区对文本做 排序行 / 去重 / 去空行 / trim / 大小写 / 编号 | 手工去别的工具洗文本 | 模板型工具 | S–M |
| **P2** | 收藏 / 最近使用 | 收藏工具落盘、最近使用会话内；侧栏置顶 + 命令面板优先 | 反复在侧栏找同一个工具 | 壳层 | S |
| **P2** | 错误行号点击跳转 | 校验错误行号可点击，输入区光标跳到该行 | 肉眼在大文本里数行 | 模板型工具 + JSON 提取 | S |
| **后置** | JSON 树视图 / 大文本查看器 | 结构性结果视图 | 大 JSON 靠滚 | JSON 系列 | L |

## 2. 形态锁定（已决策）

- **发送到**：单向发送，不做实时联动 / 管道。
- **会话历史**：每工具、只存输入、上限 20 条、纯内存。
- **文件载入**：普通载入，不按扩展名智能路由；无标签页时落到默认工具（JSON 格式化）作为落点。
- **剪贴板历史**：仅应用内，不监听系统剪贴板。
- **通用文本操作**：挂输出区工具栏，默认开启，工具可 opt-out（`ToolImpl.outputTextActions === false`）。
- **持久化**：收藏与全局开关落盘，其余会话态。

## 3. 地基（先做）

- `openTool(toolId, initialInput?)`——带初始输入开标签页（现有实现只开空标签页）。
- 统一的**文本产物出口**：输出的 复制 / 发送 / 另存 / 文本操作 收敛到一组共享组件，避免每个工具各写一份。
- 拖拽落点规则：有激活标签页 → 填入其输入；无 → 打开默认工具承载。

## 4. 落地阶段（对应提交）

1. **P0** `feat(platform): 文件载入与拖拽导入`
2. **P0** `feat(platform): 输出「发送到…」工具间传递`
3. **P1** `feat(platform): 会话历史、剪贴板历史、通用文本操作`
4. **P2** `feat(platform): 收藏/最近使用与错误行号跳转`

## 5. 需新增的领域词条（写入 CONTEXT.md）

文件载入（File Load）· 发送（Send To）· 会话历史（Session History）· 剪贴板历史（Clipboard History）· 收藏工具（Favorite Tool）/ 最近使用（Recent Tool）· 通用文本操作（Text Actions）。

## 6. 需新增的架构决策（ADR）

- **ADR-0004**：工具间传递只做单向发送，不做实时联动 / 管道（难反悔、看代码会疑惑、真实权衡）。

## 7. 交付后补齐（两处遗留）

首批落地后剩两个缺口，均已补齐：

- **错误行号曾经靠引擎报错文案反推**——只有 SpiderMonkey / 旧版 V8 给位置，
  新版 V8（Windows WebView2）与 JSC（macOS WKWebView）都不给，于是「点击跳转」
  在最常见的两个平台上是哑的。现改为复用 JSON 比对自带的位置感知扫描
  （`src/tools/json-common/scan.ts`），行号与引擎无关，格式化 / 提取 / 比对三处一致。
  这就是 CONTEXT.md 里「位置感知解析」一词的所指。
- **异形工具缺产物出口**——JSON 比对与正则测试器不是模板布局，输出区不存在，
  首批没接上「发送到…」。现各自明确「产物」形态后接入共享的 `OutputActions`：
  比对送「差异报告」（每条差异一行），正则送匹配列表（一行一个匹配项）；
  两者都是清单而非可编辑文本，故不挂通用文本操作。

仍然**有意保留**的边界：通用文本操作与自动复制只覆盖模板型工具（异形工具的产物
是清单，覆盖显示那套语义不适用）；JSON 树视图 / 大文本查看器按约定后置。
